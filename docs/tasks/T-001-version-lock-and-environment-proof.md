## Notes / gotchas

- **Never install the npm `prisma` package.** The pip `prisma` package ships its own CLI 5.19.0 and Rust
  query engine. See `docs/research/00-versions.md` §4.
- Run the spike inside `python:3.13-slim` so it matches the pinned Docker image. The local machine has
  Python 3.14.7 — record whether it also works, but the Docker result is the one that counts.
- The probe schema in `backend/prisma/schema.prisma` is a **placeholder**. T-010 replaces it with the real
  19 models. Keep it minimal (one model) and mark it as such in a comment.
- `prisma migrate dev` needs a shadow database. A single Postgres container is fine — Prisma creates the
  shadow DB itself.
- Postgres for the spike: run a throwaway container, e.g.
  `docker run --rm -d --name postly-spike -e POSTGRES_PASSWORD=spike -e POSTGRES_USER=postly -e POSTGRES_DB=postly -p 5433:5432 postgres:16-alpine`
  then `DATABASE_URL=postgresql://postly:spike@localhost:5433/postly`.
- The pip package installs a CLI. Both `prisma generate` and `python -m prisma generate` work — pick one and
  use it consistently everywhere (the canonical commands in `AGENTS.md` use `python -m prisma ...`).
- Do not commit `.venv`, the generated client, or the spike database.
